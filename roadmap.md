## Этап 2: озвучиватель манги (сделано 2026-09-26)

Фича «Озвучиватель манги» (`ChatInput` → `MangaVoiceModal` → `manga-analyze` + `dialog-tts`) дошла
до состояния «работает на реальных сканах». Что было сломано и как починено:

- [x] **Озвучка падала на «человеческом» транскрипте.** `dialog-tts` разбирает только строки
  `^Speaker N: …`, а модель и пользователь пишут «Рассказчик: …», «Аки: …», «— Привет» —
  сервер отвечал 400 «Не найдено реплик». Добавлена нормализация на клиенте
  (`src/lib/mangaTranscript.ts`): имена получают стабильные номера, реплики без автора
  остаются за предыдущим персонажем, результат гарантированно проходит серверный шаблон
- [x] **Лимиты озвучки проверяются до запроса** (8 голосов, 40 реплик для 3+ голосов) —
  вместо 400 от сервера показываем причину
- [x] **Батч из 5 сканов не влезал в запрос.** Страницы уходят inline-base64 одним JSON:
  5 × 10 МБ → десятки мегабайт. Добавлено сжатие на клиенте (`src/lib/mangaPages.ts`):
  уменьшение до 1600 px + JPEG с понижением качества до лимита 1.5 МБ, с фолбэком
  на исходник, если canvas/декодер недоступны
- [x] **`manga-analyze` падал на не-идеальном JSON модели** (`JSON.parse` по сырому ответу):
  разбор вынесен в `supabase/functions/manga-analyze/parse.ts` — заборы ```json, текст вокруг
  объекта, транскрипт-массив, обрезка полей; добавлены таймаут 120 с и понятные ошибки
  для 429/402/413/5xx
- [x] **При переоткрытии модалки все озвученные страницы стартовали одновременно**
  (`<audio autoPlay>`): у `AudioPlayer` появился проп `autoPlay` и пауза по `STOP_SPEECH_EVENT`
- [x] **Голоса персонажей** — теперь реально выбираются (в меню фича так и описана),
  карта голосов уходит в `dialog-tts`
- [x] Страницы можно удалять, есть «Озвучить всё», закрытие по Escape и клику на фон,
  object URL отзываются при удалении/переозвучке/размонтировании
- [x] Тесты: `mangaVoiceModal.test.tsx` (18), `mangaPages.test.ts` (16), `mangaTranscript.test.ts` (15),
  `mangaAnalyze.test.ts` (19, включая стражи конфига и контракта с `dialog-tts`),
  `audioPlayer.test.tsx` (6) — всего 221 тест

## Этап 3: единый метод запросов + проработка озвучки манги (сделано 2026-09-26)

За образец взят метод отправки сообщения (`useChat.sendMessage`): UI обновляется до ответа,
запрос уходит с `signal`, отмена не считается ошибкой, причина отказа от сервера доезжает
до пользователя, результат раскладывается по элементам одним апдейтом состояния.

- [x] **Общий слой запросов к edge-функциям** (`src/lib/edgeAuth.ts`): `edgeRequest` /
  `edgeJson` / `edgeBlob` — те же заголовки `Authorization: Bearer <access_token>` + `apikey`,
  обязательный `AbortSignal`, одна обработка ошибок (`{ error }` → текст → `Ошибка <код>`) в
  `EdgeRequestError`; `isAbortError` отличает «Стоп» от сбоя
- [x] **Отправка сообщения переведена на этот слой**: `sendMessage` и автораскладка
  `[IMAGE_SEARCH: …]` больше не собирают fetch руками, а в toast при сбое потока попадает
  текст сервера вместо общей формулировки
- [x] **Озвучка манги вынесена в метод-хук** `src/hooks/useMangaVoice.ts` (по образцу `useChat`):
  - анализ всей очереди страниц одним нажатием — батчи по 5 уходят последовательно,
    виден прогресс («Батч 2 из 3 · обработано 5 из 12»);
    упавший батч не отменяет уже разобранные страницы и возвращается в очередь;
  - `stop()` рвёт текущий запрос и всю очередь озвучки (в модалке появились кнопки «Стоп» —
    общая и по кадру), отмена не показывается ошибкой;
  - «Озвучить всё» не останавливается на первой неудаче: страницы, которые не удалось озвучить,
    помечаются причиной прямо на кадре, остальные продолжают очередь;
  - ошибки запросов показываются и в плашке, и в toast — окно может быть закрыто в момент ответа;
  - состояние переживает закрытие окна: страницы и готовая озвучка не теряются,
    но при повторном открытии не стартуют сами;
  - страницы/голоса читаются из ref, который синхронизируется в момент апдейта, поэтому
    «поправить реплики → сразу озвучить всё» не работает по устаревшему снимку
- [x] Серверные функции не менялись: контракт `manga-analyze` и `dialog-tts` прежний
- [x] Дев-стенд `#manga-preview` (`src/components/dev/MangaVoiceDemo.tsx`): окно озвучки
  с имитацией edge-функций, сценариями «медленный ответ / ошибка / запрос висит»
  и журналом запросов (виден `signal` каждого вызова). В production-сборку не попадает
- [x] Тесты: `useMangaVoice.test.tsx` (25 — заголовки, signal, батчи, отмена, ошибки,
  очередь озвучки, уборка object URL, стражи «метод тот же, что в чате»),
  `mangaVoiceModal.test.tsx` (23, добавлены «Стоп» для анализа и озвучки, сбой страницы
  в «Озвучить всё», сохранение результата между открытиями) — всего 251 тест
